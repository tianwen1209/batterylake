# 首页六项统计指标

[English](HOME_METRICS.md) | [简体中文](HOME_METRICS.zh-CN.md)

首页统计的是**完整原始来源的规模**，不是服务器下载子集、解压文件或转换产物的规模。下载完成、转换完成、保真检查与 benchmark 验收仍分别记录。

2026-09-08 的已知统计：40 个可见目录条目、32 个来源／实验室分组、19 年跨度（2007–2026）、2,038,307 个已知源循环、2,394 颗已知电芯、约 430.4 GB 原始发布文件。未知值不补造；缺失总数的条目数量保留在审计和汇总数据中，首页不展示统计说明或方法链接。[逐数据集审计表](home-metrics-audit.json)保留修改前后数值及来源依据。

## 统计口径

- 数据集数量只统计可见条目，版本与历史别名可以仍占一个目录条目。三个隐藏的内部条目继续计入循环、电芯、容量、年份和来源分组统计。
- “Worldwide institutions” 沿用现有定义：根据 `ref_name` 提取来源／实验室标识去重。它不是独立核实过的全球法人机构或国家数量。
- 年份跨度为 `ref_name` 中最大年份减最小年份，不代表连续测量了这么多年。
- 循环数保留各作者的定义；部分 DOD 循环不自动变成等效完整循环，时序行数和日历 RPT 行数也不作为老化循环数。
- 电芯只计已知纯数字数量，EV 和 specimens 字段继续排除。确认属于同一批电芯或其子集的条目，按分组取最大值，避免重复计数；不猜测未知的交叉重复关系。
- 容量统一为十进制：`size_mb = 字节数 / 1,000,000`，`GB = size_mb / 1,000`。采用作者发布文件的压缩或未压缩形式，不重复添加本地解压目录、标准化文件。不同上游版本的文件容量可以分别计入。部分条目只计完整测量归档、不含附属小文档，逐行依据中已说明。
- 部分发布者只提供四舍五入的大小，因此总容量约为 430.4 GB；内部原有 240 MiB 也作为历史报告值保留并换算单位。

## 后续维护

1. 更新 `js/main.js` 的 `FALLBACK_DATASETS`。数值必须描述完整来源，不能从后台下载进度直接填入。
2. `stats_scope` 设为 `full_source`；`cells_basis`、`cycles_basis`、`volume_basis` 分别记录已知、未知或不适用。容量可标为作者舍入值或历史报告值。未知状态下的 0 只是存储占位。
3. 只有已确认相同覆盖或包含关系，才设置 `cells_group`／`cycles_group`／`volume_group`。分组取最大值不适合覆盖关系尚未查清的部分交叉数据。
4. 在 `evidence` 和审计 JSON 中记录版本、来源、完整性和计数依据。
5. 运行 `python3 scripts/export_dataset_registry.py` 及 `--check`；页面加载同一仓库部署的 CSV，避免旧外部仓库覆盖本次统计。
6. 运行 `python3 -m unittest discover -s tests -p test_home_metrics.py`。测试需要 Playwright 与 Chromium，覆盖在线／离线一致性、本地子集排除、重复电芯、内部条目、EV 单位与手机布局。

身份修正逻辑不能覆盖这些统计字段。用户上传的 CSV 如果没有声明完整来源口径，数值不会自动进入首页合计。
