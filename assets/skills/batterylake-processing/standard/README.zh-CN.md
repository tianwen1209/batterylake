# BatteryLake 数据集处理与 benchmark 保真标准

[English](README.md) | [简体中文](README.zh-CN.md)

版本：2.0.0 · 2026-09-07

本标准用于将 `Raw_Dataset/dataset_xx/` 转为同级 `Processed_Dataset/dataset_xx/`，服务统一的 SOH、RUL 等 benchmark。**统一结构不得改变原始样本、信号、标签定义或实验任务。** 原始目录只读；转换代码、规范版本、参数、来源和验证结果必须可追溯。

本仓库已实施逐数据集转换，各数据集是否完成，以对应 `status.json`、验证报告和实际数据产物共同判断，不能以目录存在判断。

## 1. 必须同时满足的两层目标

**完整保真层 `canonical/`** 保存所有原始实验的可解释信息：循环老化、RPT、独立容量测试、HPPC、SOC 工况、日历老化、安全实验、不完整循环、缺失、异常、作者标签和额外通道。统一通用字段；无法映射的字段保留为有类型的扩展数据。不能只保存电流、电压、温度后声称完整保真。

**任务视图 `views/<profile_id>/`** 根据明确的 benchmark 契约，从保真层选择样本、输入窗口和标签。`cycling_aging_v2` 只收录经协议确认的老化循环；RPT 可以通过标签关联表为 SOH 任务提供目标，但不能冒充老化 cycle。日历老化按时间表达，不制造 cycle；SOC、热安全、机械实验各自保留，不强行声称适用于循环寿命预测。

原始字节可恢复、规范化信号等价、某个 benchmark 等价是三个不同结论。保留原始包或链接只能支撑来源追溯，**不能代替标准化转换和模型输入验证**。无法解码的文件必须列为未转换；不得将复制、解压、清单生成或空 CSV 标为数据集处理完成。

v1.1 中“排除 RPT”“排除不完整循环”等规定现在只约束特定任务视图，不再意味着丢弃源信息。原有两张 CSV 的通用字段继续采用，新增层次和标签契约见字段文档。

## 2. 处理前的证据与完整性

1. 清点目录中每个文件及压缩包每个成员，包括嵌套包、工作簿 sheet、MAT/HDF5 对象、JSON 层次。初始清单可以只列文件及 ZIP 中央目录，但必须明确未完成成员深查和内容校验。
2. 正式转换前为输入文件计算 SHA-256，记录大小、相对路径、上游版本、来源链接和许可证（未知写 unknown）。ZIP CRC/文件大小相同不等于内容已验证。转换后确认原始文件哈希不变；断点续跑必须检验输入、代码、配置及 schema 指纹。
3. `.part`、空文件、损坏归档、仅下载样例、缺分卷必须单独标注。不得因扩展名改名就当作下载完整。不能用已下载样例代表上游全量数据。
4. 实验类型、单位、正负号、电芯身份、循环边界和容量含义以本地作者说明、协议、元数据、原始代码为依据。必要时查官方数据页/论文并记录页码或章节。文件名仅作线索；来源矛盾时保留证据和未解决问题。
5. 同一实验常同时有 CSV/MAT、原始/作者处理版、不同发布版本。建立别名和版本映射；保留各份来源，任务视图不得重复计数，也不得默认用插值曲线替代原始测量。
6. 全数据集须有字段覆盖账本：每个源字段映射到标准列、扩展列、作者产物或明确的未转换项；每条源测量有稳定定位。视图排除项须记录数量、对象及原因，不能静默忽略。

7. 按文件魔数与实际对象结构识别格式，不能只按扩展名。特别是 `torch.save` 的 `.pkl` 可能包含多个序列化流：只读出 MAGIC 包头不代表读取了样本。必须验证完整 payload、形状、元数据、外部 storage 和 EOF；对照格式官方读取器。限制反序列化可用类型，未知类型记录错误。发现旧产物只含包头时应失效化旧 catalogue，并重建完整载荷。

## 3. 保真变换边界

- 默认只做字段映射、可逆单位转换、明确的电流符号变换、身份与来源标注。充电正、放电负；保留原始值/符号及变换公式。噪声阈值仅用于分类，不能把小电流数值直接清零。
- 不在保真层重采样、插值、平滑、去噪、裁剪、归一化、补值、删除离群点、合并重复时间点或复制行。原始重复记录也保留并标注；是否去重由任务配置明确决定。
- 数值至少保持原始精度，不统一降为 float32，不统一保留几位小数。float64 CSV 使用可往返表示；原始大整数、计数器、时间戳、Decimal 和长 ID 不得先转浮点。原始字符串、缺失标记、非有限值及无法解析的值留在 typed extras/源表示中；标准数值列空值必须带缺失原因。
- CSV 使用 UTF-8、逗号、标准引号转义；规范数值空值写空字段，禁止用 0/-1 代替。字符串空值与空字符串在字段契约/扩展表示中区分。Parquet 用真实 null；嵌套结构不得无说明扁平化或字符串化。
- 时间单位为秒，容量 Ah、能量 Wh、电流 A、电压 V、温度 °C；SOC/SOH 比例不使用百分数单位。SOH > 1 的容量恢复允许保留，不截断至 1。
- 绝对时间保留原始精度和已知时区；未知时区不得猜为 UTC。相对时间、绝对时间、step 时间、测试累计时间分开。不能先把纳秒 Unix 时间转为 float64 再相减。
- 保留记录顺序和相同时间的不同采样。时间回退/重启建立新 segment 并保留跨段顺序、原始时钟和偏移；不按电压/时间全局排序修复。缺口、重复时间和重启须显式标注。
- 多传感器、模块/支路/电芯电流、实测温度与设定温度分别保存。模块不能伪装成单电芯；已知同一物理电芯的跨文件、跨寿命阶段记录必须有共同 `physical_cell_id`。
- 未知单位不猜。可保留原字段并阻止依赖该字段的任务视图发布；无需停止其他已明确部分的工作。

## 4. 循环、容量与标签

`cycle_id` 是标准表的内部键，不是物理寿命轴。每个电芯按实验顺序从 1 编号；源循环号、真实老化累计循环数、EFC、累计运行时间及缺失区间分别保留。视图筛选不得重新编号。**不能用筛选后的行号差来计算 RUL**，也不能把一次 RPT 之间经历的 300 次 WLTP 当作一次循环。

按协议区分重复驾驶老化、诊断驾驶工况、充放电准备段。一个完整 cycle 可跨文件/segment；一个文件也可含多个 cycle。原始 cycleNumber 可能重置或不可靠，须用作者说明和 step 状态机验证，不能仅按列值 groupby。边界不明的部分保留并标记待定。

容量与 SOH：

- 分开记录额定容量、完整放电容量、部分 SOC 窗口吞吐量、RPT 参考容量、作者 Q/SOH。部分放电吞吐量不自动等于健康容量；不同倍率/温度的容量不可无说明拼为同一种标签。
- 作者给出标签时保留原值、单位、公式、基准和来源。标准派生标签另存，不覆盖作者标签。SOH 基准可能是额定容量、初始 RPT 或首个合格循环容量，必须由任务显式选择并固定，不能统一强制换基准。
- RPT 标签用 `labels` 和 `label_links` 关联到目标样本，记录测量时点、可用时点、前/后老化循环和关联方法。就近、前向填充、线性插值、事后回填必须是可追溯派生标签。未来 RPT 可以作为监督目标，但不可未经声明用来生成预测时刻的输入。
- 当需要积分推导容量/能量时，记录采用左矩形、右矩形或梯形、时间来源、噪声阈值、计数器重置规则、缺口规则及可用覆盖率。先复现作者方法，另外保存标准推导值以对照；未知时不能直接声称等价。
- 积分只跨真实连续区间，不跨缺失段、时钟重启或不确定的 step 边界；重复时间的 Δt 为 0。`Σ IΔt/3600` 不是完整算法说明，必须说明 I 对应哪个端点。不能把累计计数器的全局最大值当作某一循环容量。
- 温度平均默认在有效连续区间内按时间加权，记录积分/端点方法及有效时长；不跨缺口。只有一个点或时间不可用时留空，若任务选择算术平均则另行标明。

EOL 与 RUL：

- 保存作者 EOL 定义/事件，区分“到达阈值”“实验结束”“故障退出”。只有任务配置明确选择时才使用 `soh<=0.80` 默认阈值，并标为 `default_80pct`，不得伪装成数据集原始标签。
- 声明 SOH 阈值、首次/连续 K 次/平滑后触发规则、容量基准、比较符和时间轴。作者 EOL 与统一 benchmark EOL 并列保存。
- `rul = max(eol_axis_value - current_axis_value, 0)` 仅适用于已观测 EOL 且同一可靠寿命轴。单位可以是老化 cycles、EFC、小时或天，字段必须注明。只有真实 cycles 才写 `rul_cycles`；`eol_cycle_id` 仅作关联，不默认参与相减。
- 定期 RPT 首次低于阈值通常只证明 EOL 在上次合格测量与此次测量之间；保存区间界限或显式的“首次观测失效”约定，不能声称精确知道中间某一 cycle。
- 未观测 EOL 时记录右删失及观测终点，不能把文件最后一行当 EOL。作者 RUL、模型估计和实际观测必须区分；模型估计默认不作为真实标签。保留 EOL 后记录；是否将其纳入任务由 profile 指定。

## 5. 存储及转换程序

每个数据集至少有来源清单、字段映射、数据集说明、状态、保真层和验证报告；适用时另有任务视图。完整布局及字段见[契约](skills/batterylake-processing/references/schema.md)。

小表可用 CSV；大时序推荐无损压缩 Parquet 分片。逻辑表一致，manifest 显式列出文件、schema、行数、列类型、哈希和读取顺序；不能让 loader 猜格式或依赖文件系统枚举顺序。若两种格式都发布，必须互相核验。保真层与视图可用稳定键引用，避免为不同任务反复复制全部时序。

转换器放在 `scripts/processing/`，共享读取/校验工具与数据集 adapter 分开；规则、阈值、输入模式和 profile 配置可审计。小样本调试后必须逐文件覆盖全量；输出先进入暂存目录，通过检查再原子发布。失败保持失败记录，不留下貌似完成的半张表；断点以输入、代码、配置和 schema 指纹为依据。

逐包/逐电芯流式处理，先估算解压和输出空间。解包拒绝路径穿越，不把代码文件当数据执行；Pickle 需要审查对象类型并使用隔离环境或受限读取策略。原始作者脚本先检查依赖与作用，再用于独立对照。

## 6. 验收门槛

| 阶段 | 需要的证据 | 允许的结论 |
|---|---|---|
| I 清点 | 文件数、字节数、格式、缺件和初步类型，深查范围明确 | 已清点，不代表已转换 |
| S 语义 | 作者证据、身份/单位/边界、字段账本、标签和重复表示策略 | adapter 设计已确认 |
| C 转换 | 全文件覆盖、typed extras、可读标准表、输入/输出哈希、可重跑命令 | 已转换，尚未证明保真 |
| V 保真 | 主外键/行数/缺失/顺序/字段覆盖、原始↔标准数值全量核验、容量对照 | `canonical_validated` |
| E 任务等价 | 独立 raw loader 与标准 loader 的同一 profile 输入、标签、split、预测/训练对照 | `benchmark_verified`，仅对该 profile 有效 |

所有核心行数、身份、顺序、分类与缺失掩码须完全一致。单位转换的数值误差按字段在比较前约定绝对/相对容差，并记录最大误差、分位数、首个差异定位；不可只比较均值或随机画几条曲线。容差不能借用仪器噪声掩盖转换损失。

所谓“CNN SOH 结果无限接近原始数据”，验收为 **同样本、同特征、同标签、同划分、同预处理和同训练配置下，转换误差在事先定义的数值/实验重复性范围内**。先比较输入张量，再验证预测和训练；模型分数接近不能证明数据没有丢失。跨硬件/版本不保证逐位重现，参见 [PyTorch 官方可复现性说明](https://docs.pytorch.org/docs/stable/notes/randomness.html)。具体执行见[等价性契约](skills/batterylake-processing/references/equivalence.md)。

非 SOH/RUL 数据集也需要完成保真处理，但相应 benchmark 状态为 `not_applicable` 并给证据。缺少源数据记 `blocked_missing_source`；缺少已安装解析器记 `pending_dependency`；未知语义记 `needs_semantic_review`。未运行任何校验不能写 pass；样例通过不能替代全量通过。

cd /home/zhutianwen/BatteryLake
python3 scripts/inventory_datasets.py
# 正式转换前按数据集补充输入 SHA-256；这是只读源文件的操作：

工具输出文件清单、第一层 ZIP 成员索引与清点报告；不解压、不转换，不改动已有任务状态。TAR/RAR/嵌套 ZIP 深查在各数据集 TODO 中继续完成。首次创建的 `status.json` 明确标记未转换。
